## 运行结构

- 真实社区入口 `/live`；原 `/` 和 `/demo` 保留独立演示。宣传和邀请必须使用 `/live`。
- 单实例 Node 24/26 + PostgreSQL 17；本机文件媒体必须挂载持久卷，首版不支持多个各自独立磁盘的实例或临时磁盘/serverless部署。多实例需共享同一媒体卷，后续可替换对象存储适配器。
- 依赖在锁文件固定。`@ffprobe-installer/ffprobe` 提供视频元数据解析二进制；也可配置经过维护的 `FFPROBE_PATH`。视频最多30MiB、10分钟；图片最多5MiB，服务端转为WebP，GIF使用首帧。
- HTTPS反向代理将应用端口留在内网；入口应限制请求体32MiB并提供合理的上传超时。人物头像与帖子媒体经过实时可见性校验，不将私有媒体目录映射为静态目录，不使用会绕过隐藏权限的公共CDN缓存。

## 配置顺序

1. 先准备独立的预览/正式数据库，各自使用迁移拥有者和受限应用角色；不得将本机开发数据作为正式种子。角色操作参考 `scripts/db/local.mjs`，托管环境用其管理员控制台建立角色。
2. 提供 `DATABASE_URL`（应用）、`DIRECT_URL`（仅迁移任务）、`DATABASE_ROLE`、`APP_ORIGIN`（精确HTTPS来源）、独立的 `SESSION_PASSWORD` / `RATE_LIMIT_SECRET` / `RECOVERY_CODE_PEPPER`（各至少32位随机字符）及持久媒体目录 `MEDIA_STORAGE_ROOT`。迁移任务运行 `npm run db:migrate`，应用服务运行时不注入拥有者连接。
3. `npm ci`，`npm run check`，`npm run build`。Docker 可用时执行 `docker build -t inrole:beta .`；不要将真实环境变量写入镜像。
4. 公开目录导入必须显式审核；`db:seed:catalog`只允许本机开发库。正式环境用管理员维护公共人物/话题；不得导入演示账号、帖子、点赞或钱包。
5. 先用普通注册创建站长账号，再在可信迁移终端运行 `node scripts/db/bootstrap-admin.mjs 站长ID`。它撤销旧会话，需重新登录；网站内没有提升管理员权限的接口。
6. 在账号设置生成并离线保存一次性恢复码。恢复会撤销全部旧会话；未配置独立 pepper 时明确失败，不提供假的找回入口。
7. 热搜实时查询数据库，无需调度任务。推荐V1从最新1000篇可见帖子中结合兴趣、热度、新鲜度排序并预留探索位，不等同于机器学习模型；规模增长前需要查询性能评估和缓存失效方案。

## 备份与恢复

- 本机 `npm run backup:verify` 使用已安装的 PostgreSQL 17 工具，生成仓库外备份，恢复到全新临时库并比对所有表的数据摘要；不覆盖现有数据库。备份含账号凭据哈希和私密业务数据，需保存在受控位置；恢复演练完成后临时库自动删除。
- 正式库使用托管方自动备份/PITR并定期导出加密异地副本；媒体持久卷必须一起备份。数据库恢复点和媒体快照保持一致。恢复到新的测试库与新媒体卷，使用独立密钥、域名，再验收注册/登录、读帖、媒体和余额流水，禁止直接覆盖运行中的正式库。
- 回滚先恢复上一版本应用镜像；数据库迁移为追加式，禁止通过改写已执行迁移回滚。重大数据变更先在恢复副本验证。
- 本轮只验证本机数据库备份恢复；正式环境和媒体备份尚未验收。

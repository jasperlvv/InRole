## 0. 先定义“两周做好”是什么意思

两周能做到的是：**可邀请 5～20 人试用的质量 MVP**，不是公开运营级产品。

- 可邀请内测：真实账号、真实帖子/评论/点赞、真实评分、真实戏币账本、热搜、个人中心、基础管理、手机可用、测试与备份。
- 公开运营还缺：ICP/公安备案、内容安全 API、账号找回、法务文本、风控、监控告警、正式域名与备案。这些不塞进两周，避免“看起来上线、实际不能用”。

前提条件（缺一项就会延期）：

1. 每天能拿出 30～60 分钟做验收和反馈；云控制台操作由你完成。
2. 产品规则冻结，不在开发中加图片、私信、关注、视频、转发。
3. Git 作者信息、Supabase、Vercel 账号可用；D1 就验证 Vercel 在你手机网络能打开。
4. 接受“先 beta 后公开”：两周内用 Vercel 域名，不办 ICP，不接支付。

## 2. 技术基线（D1 锁定，避免中途换栈）

- Next.js 16.4.6、React 19.3.1、TypeScript strict、Tailwind CSS 4、npm + lockfile。
- 路由：App Router；`src/app`、`src/components`、`src/lib`、`src/server`。
- 数据库：Supabase PostgreSQL；服务端用 Drizzle ORM + `postgres` 驱动；浏览器不直连数据库。
- 认证：优先 Auth.js Credentials；D6 做 60 分钟兼容性验证。若与 Next 16 不兼容，改用 Better Auth 的用户名/密码方案，写决策记录；不自制 Cookie 加密。
- 校验：Zod；测试：`node:test` + Playwright；错误统一 JSON envelope。
- 不引入 Docker、Redis、Kubernetes、重型 UI 框架；不做图片上传。
- 热搜：SQL 窗口统计 + 5 分钟按需缓存，不依赖付费 cron；这比“每 10 分钟定时任务”更适合两周交付。
- 部署：Vercel + Supabase Singapore；D1 验证手机网络，打不开当天换托管，不拖到 D13。

## 5. 每天固定检查（Definition of Done）

每个任务结束前必须满足：

1. `npm run lint`、`npm run typecheck`、`npm run test`、`npm run build` 通过；未运行要写明原因。
2. 新增业务规则有测试：ID/长度/评分/热度/币并发至少覆盖。
3. 手机 360/390 和桌面 1440 检查；无横向溢出，底栏不挡按钮。
4. 空、加载、错误、无权限四种状态都有真实 UI。
5. 真实模式失败不回退假数据；演示模式明确标识。
6. `docs/进度清单.md` 更新；`docs/verification/Dxx.md` 记录命令、结果、截图、未验证项。
7. Git 提交，提交信息写清任务编号；不提交 `.env.local` 和密钥。
8. 给我预览地址和 3～5 步验收动作。

## 6. 延期时砍什么

按顺序砍，不碰安全与账本：

1. S14 推荐 V1 → 先只做热门/最新，beta 后再加。
2. 管理后台 UI → 先保留举报列表 + 隐藏 + 封禁三个动作，人物/话题用种子/SQL 维护。
3. 搜索 → 先保留人物/话题的简单 `ILIKE`，不做全文搜索。
4. 自定义域名/备案 → beta 用 Vercel 域名。
5. 密码找回 → 内测只做已登录改密；公开注册前补恢复码。

**不能砍**：真实认证、服务端权限、帖子/评论/评分、币事务与幂等、备份、关键测试、手机可用性。

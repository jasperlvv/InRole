# P2 修复：封禁可见性与分页竞态

日期：2026-11-26。基线提交 `233df1d`，版本 `0.2.0-rc.1`。对应 [2026-11-26 项目检查](2026-11-26-project-review.md) 中记录的两项 P2。

## 修复 1：封禁后的引用与媒体不再泄露

原来只有帖子详情查询带作者状态条件，引用和媒体各自判定，导致封禁后出现“原帖 404、引用仍带原文、图片仍可直取”。现在三处统一为同一条规则：**帖子 `visibility='VISIBLE'`、作者 `status='ACTIVE'`、且未被查看者屏蔽**。

| 文件 | 改动 |
| --- | --- |
| `src/server/posts.ts:28` | 引用的 `quotePost` 选择补充 `author.status` |
| `src/server/posts.ts:33` | 新增 `quoteDTO()`，可用性判断统一走“可见 + 作者 ACTIVE + 未屏蔽”，下发给前端的作者字段只保留 `handle`/`displayName` |
| `src/server/media.ts:67` | 帖子媒体查询补充作者状态 |
| `src/server/media.ts:70` | 公开判定改为“帖子可见且作者 ACTIVE”，并复用已取得的 `viewer`，不再重复调用 `optionalActor()` |
| `src/server/community-write.ts:42` | `visiblePost()` 用 `JOIN app_users ... status='ACTIVE'` 限定作者状态，行锁改为 `FOR SHARE OF p` / `FOR UPDATE OF p` |

`visiblePost()` 同时被引用、评论、点赞、投票、赠送通宝和举报目标校验使用，因此封禁作者的帖子在这些入口统一返回 404，不再出现“读不到却还能互动”。

管理端 `post.hide` 的语义不变：隐藏仍按帖子 `visibility` 处理，与封禁是两条独立路径，解除封禁后内容自动恢复可见（因为判定读取的是当前状态，不写历史标记）。

## 修复 2：切换筛选时分页请求被取消

`src/components/live-stage.tsx` 的 `more()` 原来不传 `AbortSignal`，也不校验请求归属，慢网下会出现“旧分页结果追加到新列表、旧游标覆盖新游标，下一次分页返回 400”。

现在的行为：

- 首屏 effect 的清理函数同时 `abort()` 正在进行的分页请求；
- 分页请求自己持有 `AbortController`（`moreAbort` ref），响应返回后先判断 `signal.aborted`，已取消则直接丢弃，不写入 `items`/`page`；
- 分页失败只在未取消时记录错误；已取消的请求不会把 `loading` 留在永久加载状态，由新首屏请求收尾。

服务端的筛选绑定校验保持不变（`posts?person=...&cursor=...` 混用游标仍返回 400），客户端不再产生这种组合。

新增回归场景：**“banned authors' posts disappear from quotes, media and interactions and return after unban”**（`scripts/db/verify-community.mjs`）。它在隔离临时库中注册账号、带图片发帖、由另一账号引用，然后：

1. 封禁前：直链 200、引用 `unavailable:false`、媒体 200；
2. 封禁后：直链 404、引用 `unavailable:true`、媒体 404、评论列表 404、点赞/评论/赠送/新建引用全部 404，列表与推荐不再出现该帖；
3. 解封后：直链恢复、引用恢复、媒体恢复 200。

## 未验证与限制

- 分页竞态属于客户端时序问题，**没有自动化测试覆盖**；本仓库按 `AGENTS.md` 保持浏览器自动化停用。需要人工在浏览器开发者工具把网络限速到 Slow 3G，执行“加载更多 → 立刻切话题”确认列表不混入旧内容。未执行，不声明已验证。
- 真机、慢网、大陆/海外网络验收仍未做；S16 不能因此整项标完成。
- Linux 容器、正式 HTTPS、生产备份恢复仍未实测。
- `verify:community` 会重写 `docs/verification/S09-S15-result.json`；本次同时把该文件的日期从写死的 `2026-11-25` 改为运行时日期，避免覆盖后出现与报告不一致的旧日期。

## 影响面与兼容性

- 无数据库迁移，无 schema 变更，可回退到上一版本应用。
- 唯一行为变化：作者处于 `BANNED`/`CLOSED` 状态时，其帖子在引用、媒体、互动入口一律 404（与详情一致）；解封自动恢复。
- 已解除封禁的账号不需要额外数据修复。

# InRole 网站直接上线：三步方案

版本：V2.0。2026-11-25，北京时间。

最新用户决定：**取消小范围内测，直接推进网站正式上线；要求中国大陆与海外可访问；iOS、安卓等网站稳定后再考虑。** 本方案替代上一份22步指南中的执行顺序。保留开发测试和上线检查，不再要求招募5人/20人、等待反馈或先做移动端。本次交付是方案，尚未购买域名、创建云资源或部署。

## 推荐架构和访问目标

优先评估：**一个可注册的.com域名 + 香港区域Linux云服务器 + Docker Compose运行Next.js、PostgreSQL、Caddy + 持久数据卷 + 异机加密备份。** 首版单节点保持现有业务，减少新增服务和代码改造；规模扩大后再考虑托管数据库和私有对象存储。单节点存在故障集中风险，备份、恢复和监控在第三步一并完成。

这是工程建议，不代表已经确定云厂商、套餐、域名或费用。.com便于品牌统一，但不会自动获得国内外连通性；真正影响访问的是DNS、服务器线路、HTTPS、前端依赖和用户网络。优先实测候选节点，不承诺所有地区/运营商永远可达或同样快速。

域名注册在你名下，选择可管理DNS、可转出、续费清楚的注册商；若未来可能迁入大陆节点，提前核对域名注册渠道和实名材料能否用于备案。首年价格、续费、云服务器流量与超额费用分别核对，不提前购买多年套餐。

香港节点的接入备案要求与大陆节点不同；如果使用大陆服务器或大陆CDN节点，需要核对相应ICP备案等条件。香港主机也不能替代面向大陆公开社区运营的适用义务，尤其发帖/评论的真实身份认证、内容管理和隐私规则。当前ID+密码产品规则保持不变，若适用要求需要新增认证，应先明确方案、由你决定，不擅改为手机号注册，也不声称现有实现已满足全部要求。

来源：[云厂商ICP备案与DNS说明](https://www.alibabacloud.com/help/en/dns/icp-and-dns)、[大陆CDN接入限制](https://www.alibabacloud.com/help/en/cdn/product-overview/limits)、[互联网用户账号信息管理规定第九条](https://www.cac.gov.cn/2022-06/26/c_1657868775042841.htm)。

**通过条件：**核心流程和权限检查通过；已知阻断清零；构建成功；真实手机/电脑未测项明确记录；部署材料可审查。隔离测试库验证不操作正式数据。涉及适用运营要求的未决项明确写进发布清单，不伪装为技术已解决。

## 第2步：一次确定域名、服务器、费用和接入

**我来完成：**

- 根据你能使用的云账户和预算，优先比较香港节点，选一个适合当前持续Node服务、PostgreSQL及视频上传的方案。初始可将2核4GB作为评估起点，最终按镜像构建、运行与上传实测调整，不能当容量保证。
- 查域名可注册性和续费价格，给出少量可用.com候选；必须实际查询，不把示例域名当成可购买。已持有域名则优先复用。
- 一张表列清：域名、服务器、系统盘/持久存储、带宽/流量、备份、续费和预计月成本；有付费内容过滤等附加项时单列。
- 核对大陆与海外访问路径：DNS查询、TCP/TLS、页面静态资源和API。有官方试用/现有探测条件时先验证；不把本机一次curl或“全球节点”宣传当跨境实测。
- 核对服务类型与拟服务地区的接入/运营条件，并明确现有ID密码规则的未决点。若香港候选节点无法满足访问目标，先调整节点/线路或提出大陆合规部署备选，再购买。
- 给出具体购买规格与最短配置说明；能用现有账户和资源就复用。正式连接优先用SSH密钥或云厂商安全授权，不让你把密码、密钥、恢复码贴进对话。

**你来完成：**确认一个域名、费用上限和公开运营方案；在你控制的账户完成必要注册、实名、付款、手续和安全授权。购买是这一阶段的最终确认点，先给你可审查的具体结果。

**通过条件：**域名归你控制、资源规格和续费清楚、正式目标域名确定、部署访问可用、适用要求和账号规则有明确处理方案。不得把“买到香港服务器”记作“国内外访问已验收”。

**复制提示词：**

> 执行《InRole网站直接上线三步方案》第2步，为InRole选定一个可从中国大陆和海外访问的网站部署方案。优先评估可注册.com域名、香港Linux单节点、Docker Compose运行Next.js/PostgreSQL/Caddy、持久卷和异机备份。先检查我已有资源；实际核对域名可用性、续费、服务器规格、流量费用与访问线路，给出一套首选配置、完整费用表和必要的接入/运营条件。结合现有ID密码产品规则说明待决定事项，不擅自更改注册方式；如果访问效果不合格，提出替代节点或线路。先把购买与配置内容做到可审查，再让我一次确认域名、预算和必要账户操作；不索取聊天中的明文密码或密钥，不提前购买收费资源，不安排内测或移动端。

## 第3步：部署、跨网络验收，然后开放正式网站

**我来完成：**

- 从第1步确定的Git版本构建并部署；数据库初始化采用专用拥有者，应用仅使用受限账号，数据库端口不公开。正式库使用全新生产数据，不导入演示账号、帖子或钱包。
- 配置域名DNS、HTTPS及证书续期、统一主域和跳转、精确APP_ORIGIN、可信代理头、Cookie、上传大小/超时、防火墙、自动重启和限流。媒体不直接映射为绕过授权的公开目录。
- 设置应用、数据库、媒体及TLS状态持久化。秘密由环境/秘密管理注入；运行服务不获得迁移拥有者连接。导入经审核的公共人物/兴趣/话题，配置站长管理员与恢复码。
- 配置自动数据库与媒体备份、主机外副本、容量/服务/备份/费用告警；在新位置完成恢复演练。保存上一版本及回滚办法。
- 在开放公开注册前，用明确标记的发布检查账号验证真实HTTPS下注册/登录、帖子/评论、媒体、评分、通宝/钱包、举报/管理、屏蔽/注销；妥善处理检查数据，保留必要一致性记录。这是发布检查，不是招募内测。
- 取得中国大陆和海外至少各一个真实网络的访问证据，记录地区/网络/时间、DNS/TLS、首页、登录、发帖和媒体结果；大陆再覆盖手机蜂窝或家庭宽带。可由你实际设备/可信参与者/已授权远端探测提供，缺少地点就如实记未验证，不能捏造海外测试。
- 测试服务重启与重新部署后的会话、帖子和媒体。若关键功能失败、存在数据/权限风险、访问目标不达标或实际适用发布手续未完成，修复或解决后再开放对应服务。
- 达到约定发布条件后开放正式站点，给出网址、版本、检查记录、备份/恢复位置说明和维护方式；上线后重点观察错误、媒体容量和举报队列。

**你来完成：**配合真实网络与手机检查；完成必须由账号持有人进行的授权/手续/确认；保存管理员恢复码，持续处理用户反馈与举报。

**通过条件：**实际取得大陆与海外访问记录，主要业务通过生产环境检查，电脑关闭后网站可运行，重启不丢文件，备份能恢复，公开联系方式及适用手续完整。未获得的网络证据明确列为待验证，不宣称全球可达。

**复制提示词：**

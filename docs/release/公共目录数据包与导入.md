# 公共目录数据包与导入

更新：2026-11-26。对应工具：`scripts/db/import-catalog.mjs`（命令 `npm run db:import:catalog`）、校验逻辑 `scripts/db/catalog-pack.mjs`、集成验收 `npm run verify:catalog`。

## 现状

| 内容 | 状态 |
| --- | --- |
| 导入工具 | 已实现，8 组集成场景通过 |
| `prisma/catalog.json`（22 位人物 / 9 兴趣 / 8 话题 / 22 条署名） | 可直接导入正式库 |
| 270 位候选名单（`人物扩充候选清单V2.md`） | 只有姓名与分组，还不是数据包 |

名单不是数据包：缺少人物标识、简介、兴趣归属、头像文件和来源署名。工具会逐项校验，缺一项就拒绝写入，不会导入半成品。

## 数据包结构

```json
{
  "version": 1,
  "reviewedAt": "2026-11-26",
  "reviewedBy": "审核人",
  "interests": [{ "id": "literature", "name": "文学诗词" }],
  "topics": [{ "id": "poetry", "name": "诗词接龙", "description": "用一句诗接上故事。", "interestId": "literature" }],
  "people": [
    {
      "id": "libai",
      "name": "李白",
      "aliases": ["李太白", "青莲居士"],
      "bio": "唐代诗人，以想象丰富、语言奔放的诗作闻名。",
      "primaryInterestId": "literature",
      "interestIds": ["history-cn"],
      "legacyAvatarPath": "/people/libai.webp",
      "source": {
        "title": "File:Libai touxiang.jpg",
        "sourcePage": "https://commons.wikimedia.org/wiki/File:Libai_touxiang.jpg",
        "author": "Unknown author",
        "license": "Public domain",
        "licenseUrl": "https://creativecommons.org/publicdomain/mark/1.0/",
        "changes": "Square crop, resized and converted to WebP."
      }
    }
  ]
}
```

`source` 可以省略：省略时按 `id` 从 `src/lib/portrait-sources.ts` 取署名，这就是现有 `prisma/catalog.json` 的形态。两边都取不到署名，导入直接失败。

## 字段规则

| 字段 | 规则 |
| --- | --- |
| `id` | `^[a-z0-9][a-z0-9-]{1,63}$`，一旦用于正式内容就是稳定标识，改名不改 id |
| `name` | 1–60 字，包内唯一 |
| `aliases` | 最多 6 个，每个 1–40 字；与其他人物姓名撞车只警告 |
| `bio` | 1–280 字，公开可见，不要写“此处为用户扮演”以外的版权不明内容 |
| `primaryInterestId` | 必须存在于包内 `interests` 或目标库 |
| `interestIds` | 可选，附加兴趣；同样必须在包或库中存在 |
| `legacyAvatarPath` | 只能是 `/people/<id>.webp|png|jpg`，或留空（显示首字占位） |
| `source.*` | 作品名、来源页、作者、许可证、许可证链接缺一不可，两个链接必须是 https |
| `topics[].interestId` | 必须存在 |
| `version` | 当前为 `1` |
| `reviewedAt` / `reviewedBy` | 正式写入必填；也可由命令行 `--reviewed-at` / `--reviewed-by` 声明 |

## 命令

在仓库根目录（服务器上是 `/opt/inrole`）：

```bash
npm run db:import:catalog -- --check                       # 只校验 JSON，不需要数据库
npm run db:import:catalog -- --pack prisma/catalog.json    # 演练：连库、打印计划、不写入
npm run db:import:catalog -- --pack prisma/catalog.json --apply --confirm-reviewed \
  --reviewed-at 2026-11-26 --reviewed-by 你的名字           # 正式写入
```

正式写入前必须加载迁移拥有者凭据（`DIRECT_URL`），应用连接串没有目录写入权限：

```bash
set -a; . /etc/inrole/migrate.env; set +a
```

工具内建的保护：

- 默认拒绝 `inrole_dev`、`inrole_test`、`inrole_verify_*`（要覆盖需显式 `--allow-development`，仅用于验收脚本）。
- 只做 `INSERT ... ON CONFLICT DO NOTHING`；管理后台改过的简介、头像、启用状态不会被覆盖。
- 整个导入是一个事务，附带 advisory lock 防止两个进程同时写；任一条失败全部回滚。
- 写入后核对：数据包内每个人物都在库中，且都有署名。
- 输出回执 `.tmp/catalog/import-<时间>.json`，含目标库、数据包摘要、审核人、各表增量；不含任何连接串。回执应与发布记录一起归档。

## 从 270 位名单到数据包

1. **定 id**：把名单里的人名逐个转成英文短 id（如 `li-shimin`、`jackie-chan`），冲突就先占位，之后不再改。
2. **写简介**：一句到三句，说明身份、时代/作品，以及必要时区分史实与演义/影视版本。
3. **定兴趣**：现有 9 个兴趣可能不够（名单里有体育、动漫）。新增兴趣必须先放进 `interests`，否则人物会引用到不存在的标签。
4. **处理头像**：两条路——把图片放进 `public/people/` 并写 `legacyAvatarPath`；或先不写头像，上线后用后台“上传人物头像”逐张补，此时显示首字占位。
5. **补署名**：每个用了头像的人物必须能追溯到作品名、来源页、作者和许可证。影视截图、游戏立绘、现代摄影的授权依据不同，要分别确认。
6. **分批**：一次导入 50～100 位，先 `--check`、再隔离库演练、再正式库写入，避免一次性 270 条错误难定位。

## 限制

- 工具不写媒体文件：`public/people/` 的图片需要随代码一起提交，后台上传的头像走独立媒体接口。
- 工具不删除、不停用人物，也不修改已有行；下架和改名走管理后台并留审计。
- 工具不校验头像图片本身是否可解码，只校验路径格式和署名完整。
- 270 位名单的最终取舍、作品版本标注和授权判断是人工审核工作，工具只保证“没补齐就导入不进去”。
